# Android 多模型性能报告

状态：阶段 B 进行中。当前先记录设备基线；0.5B/1.5B/3B 必须使用
`BENCHMARK_PLAN.md` 的同一协议完成后才能给出最终模型推荐。

## 测试设备

| 项目 | 数据 |
|---|---|
| 厂商/型号 | HONOR PTP-AN00 |
| Android | 16 / API 36 |
| ABI | arm64-v8a |
| 物理内存 | 15,632,952 KiB（约 14.9 GiB） |
| 采样时可用内存 | 3,474,964 KiB（约 3.31 GiB） |
| 采样日期 | 2026-08-29 |

该设备物理内存充足，但 Android 在采样时只报告约 3.31 GiB 可用内存。按当前保留
1 GB 的保守策略，默认推荐上限为 1.5B；3B 需要在清理后台后通过实际加载和持续
压力测试才能认证，不能仅根据总内存放行。

## 制品与初步真机结果

三档权重均通过 `tensor-cache.json` 全分片校验，并已合并进同一个 Android Runtime。
下表是同一句短提示的单轮 smoke test，不是最终统计结果：

| 模型 | 权重字节 | 分片 | Prefill | Decode | 真机状态 |
|---|---:|---:|---:|---:|---|
| Qwen2.5-0.5B q4f16_1 | 277,996,288 | 8 | 5.8 tok/s | 12.5 tok/s | 加载、生成成功 |
| Qwen2.5-1.5B q4f16_1 | 868,547,584 | 30 | 4.1 tok/s | 36.1 tok/s | 加载、生成成功 |
| Qwen2.5-3B q4f16_1 | 1,736,187,904 | 62 | 0.9 tok/s | 15.1 tok/s | 加载、生成成功，但首轮明显较慢 |

3B 模型编译器估算参数约 1,655.76 MB、临时缓冲约 55.08 MB；2048 上下文的
KV cache 还会增加占用。Android `dumpsys meminfo` 不完整覆盖 GPU 驱动分配，因此
不能用进程 PSS 代替模型峰值内存。

单轮数据存在预热、GPU 频率和后台负载噪声，尤其 0.5B 的 decode 结果不应直接
解释为比 1.5B 更慢。最终结论必须使用 Benchmark Runner 的一轮预热加三轮测量，
并补齐 20 轮稳定性和温升测试。

当前阶段性判断：1.5B 仍是默认模型首选；3B 作为手动 Quality 档，不自动推荐。
最终报告还需填写加载时间、首 token、峰值 GPU/系统内存、三轮统计、20 轮成功率、
温升和模型切换结果。没有真机测量的数据不得用估算值代替。
